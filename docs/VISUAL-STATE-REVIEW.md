# Same-brief visual state review

Use this review record for a frozen Visual brief before claiming a rebuilt page is better. It is a decision aid, not a deterministic taste score or a replacement for a blind critic. Keep the losing page and its exact host-framed film fixed; do not quietly reshoot it after making the new page. Name any unequal delivery conditions.

1. **Before building:** write five different concept mechanisms, each with claim, subject-specific rule, starting state, user action and payoff. Strip style and compare each against a plain, well-typeset page carrying the same honest content. Make desktop and 390×650 sketches with the real words and an allowance for the host header. Ask the blind critic to reject weak mechanisms before choosing one. A layout variation is not a new concept.
2. **Freeze the comparison:** record brief, source revision, concept choice and rejection reasons, asset origin/license, delivery frame, viewport, critic identity and baseline score. For each user-visible claim, quote the source or name an authored interpretation. In particular, do not promise a person-specific garment result if only a generic workshop scene is shown.
3. **Material and scene identity:** when the UI claims a localized selection, capture settled before/after frames at the same camera, crop, zoom and lighting. Mark the changed object and at least two anchors that should remain stable (such as hands, tools, furniture, background). Run `python scripts/visual-region-review.py before.png after.png regions.json --threshold 20` with `regions.json` shaped as `{"regions":{"material":[x0,y0,x1,y1],"hand":[...],"tool":[...],"background":[...]}}`. Record coordinates and frame times. A high anchor change is an investigation cue, not a universal fail threshold; camera drift, compression, moving hands and lighting may explain it. Inspect pixels yourself. A low object change does not establish a meaningful product consequence. If the whole scene tints, describe it as a scene grade, not selected cloth.
4. **Consequence and opening:** hide headings, state labels and decorative captions. Compare settled start/end and a plain baseline. Name what a viewer can see change about the actual subject, not the control value. Inspect the real host-framed desktop and 390×650 opening: object, claim, control and evidence must be legible together. No full-page capture or below-fold endpoint substitutes for this first view. Note the host header height and visible content rectangle.
5. **Transition ledger:** record each start, midpoint, end and reverse capture with timestamp, input action, source revision, viewport, reduced-motion setting and digest. State which transitions were actually exercised and which are untested. Six capture slots can be static-equivalent. Test keyboard, reverse, script-off, reduced motion and a later section separately; inspect the settled frame, not only DOM or labels. REX's capture hash summary is informational, not visual verification.
6. **Decision:** ask the same independent critic to assess the new work against the fixed baseline, at both widths and with transitions clearly evidenced. Keep the rating, dissent and defects. If it does not improve, stop rather than calling custody acceptance a visual win. One bounded prototype and no more than one revision for the study.

Record observations and remaining uncertainty, not a pass generated by a pixel score. The local diagnostic uses Pillow only when explicitly invoked; it is not part of REX's Rust/npm CI or an automatic acceptance gate.
